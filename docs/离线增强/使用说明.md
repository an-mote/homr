# HOMR 离线增强使用说明

当前仓库根目录是合入 2026-10-12 上游修复后的增强代码。2026-10-04 的原始完整增强包单独保留在发行附件中，两者版本不同。所有三个 ONNX 均沿用原版权重；GPU 第 200 步微调检查点不属于本次交付。

## 使用当前代码

先按仓库原有说明准备 Python 与 CPU 推理依赖。安装依赖和首次取得模型需要网络，准备完成后的识别可以断网执行。

从[发行附件](https://github.com/an-mote/homr/releases/tag/homr-enhanced-20261014)下载 `homr-models-20261004.tar.gz`，在仓库根目录执行：

```sh
tar -xzf homr-models-20261004.tar.gz --strip-components=1 -C .
python -m homr.main /绝对路径/乐谱.png --gpu no
```

文件校验值见同页的 `SHA256SUMS`。单个模型的路径、大小与 SHA-256 见[模型清单](模型清单.json)。模型仍被 Git 忽略，附件提取不会修改跟踪中的源码。模型包只含音乐识别的三个 ONNX；标题 OCR 使用所选 Python 环境的 RapidOCR 资源，断网运行前也需准备好。

失败会返回非零退出码并保留已有结果。多页合并输出位于输入旁边，保留逐页 MusicXML；合并名称与本次单页输出相撞时选择新的编号后缀。识别完成仍须独立打开 MusicXML 对照原谱，不能把能打开文件当作音乐正确。

## 复现原始增强包

下载 `homr-enhanced-20261004.tar.gz` 后解包：

```sh
tar -xzf homr-enhanced-20261004.tar.gz
```

得到 `homr-enhanced-20261004/`，其中包括固定源码、三个模型和 `增强版本.json`。该包与原版提交 `863eb3c6487f3c6fe50267fb71613f05162bb7c5`、最终补丁 `b360d5b5052bae0dcddc7b71992afc8aa1c022f7cba4eef61243a6e3ebe97b6a` 对应。逐文件清单见 `Tools/homr增强/版本锁.json`。

`Tools/homr增强/运行.py` 是原实验的严格 Docker 启动器，只接受原始包及固定镜像 `sha256:022a28d696700ef35452142029eee064e95f659bfa48ebfcafd54f0b5b1bafb8`。该镜像是原实验环境，没有在本发行中重新发布；缺少它时请在准备好的 Python 环境内运行原始包，不要把任意重建镜像当作完全相同的实验环境。

```sh
cd homr-enhanced-20261004
python -m homr.main /绝对路径/乐谱.png --gpu no
```

原始包没有本次移植新增的尾部诊断保留、连音诊断兼容和合并文件名碰撞修复。日常开发与使用以当前 `develop` 分支为准，历史包用于复现原有结果。
